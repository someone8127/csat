# 문제 추가 가이드

## 전체 흐름

```
시험지 1회분  ──►  data/src/<시험ID>.json  ──►  npm run build:data  ──►  data/bank.js  ──►  각 페이지가 읽어서 표시
 (직접 입력)        (사람이 편집하는 원본)         (검증 + 변환)          (자동 생성, 수정 금지)
```

- 사람이 만지는 파일은 **`data/src/*.json` 하나뿐**입니다. (시험지 1회분 = JSON 1개)
- `data/bank.js` 는 빌드 결과물입니다. 사이트는 이 파일만 읽습니다.
- 학년 페이지(`first/second/third.html`)와 유형 페이지(`type.html?t=...`)는 **같은 문제은행을 필터링**해서 보여 줍니다.
  그래서 문제를 한 번만 넣으면 학년별·유형별 양쪽에 자동으로 나타납니다.
- `file://` 로 열어도 동작하도록 JSON을 `fetch` 하지 않고 `<script>` 로 불러오는 구조입니다.

## 3단계로 추가하기

### 1) 시험지 뼈대 만들기

```bash
npm run new-exam -- 2025-06-g3 고3 "2025학년도 6월 고3 모의고사"
```

`data/src/2025-06-g3.json` 이 18~45번 빈 문항(`"status": "todo"`)과 함께 생성됩니다.
`todo` 문항은 빌드에서 제외되므로, **채운 문항만 골라서** 사이트에 올릴 수 있습니다.

### 2) 문항 채우기

문항을 채운 뒤 `"status": "todo"` 줄을 지웁니다.

```json
{
  "number": 31,
  "title": "다음 빈칸에 들어갈 말로 가장 적절한 것을 고르시오.",
  "passage": "영어 지문 ... [[BLANK]] ... 영어 지문",
  "options": ["선지1", "선지2", "선지3", "선지4", "선지5"],
  "answer": 3,
  "explanation": "해설 (줄바꿈은 \\n)",
  "translation": "지문 번역"
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `number` | O | 18~45. **이 번호로 유형이 자동 결정**됩니다. |
| `title` | O | 발문(문제 지시문) |
| `passage` | O* | 영어 지문. 빈칸은 `[[BLANK]]`, 문단 구분은 `\n\n`. (*`image`가 있으면 생략 가능) |
| `options` | O | 선지 5개. `①` 같은 번호는 쓰지 않습니다(자동 부여, 써도 제거됨). |
| `answer` | O | 정답 번호 1~5 |
| `explanation` / `translation` | 권장 | 비어 있으면 빌드 경고, 화면에는 "아직 등록되지 않았습니다" 표시 |
| `type` | 선택 | 번호 규칙을 덮어쓸 때만 사용 (아래 표의 key) |
| `image` | 선택 | 도표·그림 경로. 예: `assets/img/2025-06-g3-25.png` (25~28번 도표 문제) |
| `sharedWith` | 선택 | 장문 공통 지문. 41~42번처럼 지문이 같으면 `"sharedWith": 41` 로 지문 중복 입력을 피함 |

여러 케이스(도표, 장문 공통 지문)의 예시는 `data/src/_template.json` 에 있습니다. (`_` 로 시작하는 파일은 빌드 제외)

### 3) 빌드하고 확인하기

```bash
npm run build:data     # 검증 + data/bank.js 생성
```

- 오류가 있으면 **파일명 + 문항 번호**와 함께 이유를 알려 주고, `bank.js` 를 건드리지 않습니다.
  (선지가 5개가 아님 / 정답이 1~5가 아님 / ID 중복 / JSON 문법 오류 등)
- 성공하면 학년·유형별 문항 수 요약이 출력됩니다.
- `index.html` 을 열어 확인한 뒤 `git add . && git commit && git push` 하면 GitHub Pages에 반영됩니다.
  (`data/bank.js` 도 **반드시 커밋**하세요. 사이트가 읽는 파일입니다.)

## 문제 번호 → 유형 규칙

| key | 유형 | 번호 |
|---|---|---|
| `purpose` | 목적 및 심경변화 | 18~19 |
| `gist` | 지문 요지 및 함의추론 | 20~24 |
| `data` | 도표 및 일치·불일치 | 25~28 |
| `grammar` | 어법·어휘 적절성 | 29~30 |
| `blank` | 빈칸추론 | 31~34 |
| `order` | 무관 문장 및 글의 순서 | 35~37 |
| `insert` | 문장삽입 | 38~39 |
| `summary` | 요약 완성 및 장문 독해 | 40~42 |
| `story` | 소설 독해 | 43~45 |

이 표의 **단일 출처는 `js/config.js` 의 `TYPES`** 입니다. 구간을 바꾸거나 유형을 추가하면
유형 목록 페이지, 필터, 빌드 스크립트가 모두 자동으로 따라갑니다.
(시험마다 번호 배치가 다르면 해당 문항에만 `"type": "blank"` 처럼 지정하세요.)

## ID 규칙 (오답노트·통계와 연결되는 값)

`{exam.id}-{number}` 예) `2025-06-g3-31`, `2024-09-g3-41`

- 한 번 정하면 **바꾸지 마세요.** Step 3·4에서 Firestore에 저장되는 풀이 기록과 오답노트가 이 ID를 키로 사용합니다.
- 시험 ID 권장 형식: `연도-월-학년` (예: `2025-06-g3`, 고1·고2 교육청은 `2025-03-g1`)

## 입력할 때 지켜야 할 것

1. **원문 사용 허락 범위 확인.** 평가원·교육청 문항의 저작권은 해당 기관에 있습니다. 게시 전에 각 기관의 이용 조건(비영리 여부, 출처 표기, 재배포 범위)을 확인하세요.
2. **해설·번역은 직접 작성.** 시중 교재·학원 자료의 해설과 번역을 그대로 옮기면 별도의 저작권 문제가 생깁니다.
3. 도표 이미지는 시험지 캡처 대신 **직접 다시 그린 이미지**가 안전합니다.
4. 같은 문항을 두 번 넣지 않도록 `exam.id` 와 `number` 조합이 유일해야 합니다. (빌드가 검사)

## 앞으로 문항이 많아지면

문항이 수백 개를 넘으면 `bank.js` 한 파일이 커집니다(대략 문항당 2~3KB). 그때는 빌드 스크립트가
학년별로 `bank-g1.js`, `bank-g2.js`, `bank-g3.js` 로 나누고 각 페이지가 필요한 파일만 불러오게 바꾸면 됩니다.
페이지 코드(`solver.js`)는 `window.QUESTION_BANK` 만 보므로 수정 범위가 작습니다.
